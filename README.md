# 更好的击键当量（better-keystroke-timing）— 条件击键当量建模

> **命名说明（2026-09-29）**：项目目录已由 `击键测速` 改名为 **`串击击键当量`**（与姊妹项目 `并击击键当量` 对齐命名）。
> **数据文件 `数据/击键测速数据.tsv` 与 GitHub 仓库名 `better-keystroke-timing` 未改名**，脚本与路径引用一律照旧。

**条件击键当量**（Conditional Keystroke Equivalent，简称"当量"）：从个人打字测速数据中学习**前后键条件下**键位间的击键时间成本（ms，非物理距离），输出按键时间母表与 2/3/4 键总当量表（错误成本内含），用于输入法编码方案评估与键位优化。

**摘要**：传统键位成本模型用 2 键当量逐对累加，假设"打完一个键手就回位"。实测表明该假设系统性低估整串耗时，且低估幅度按键对类型不均（跨手 +32ms → 同手异指 +86ms，§5.4）——用其评估编码方案约 20.3% 的排序会被扭曲。本项目以"对称条件段"为单位建模：每段时间 `S(p,a,b,n)` 同时以前两键与**后继键**为条件，总当量 = 段当量之和；错误成本按段类计入，段当量 = 按键时间 + 错误成本（§4.6-§4.7）。固定 trial 测试集上总时间 MAE 35.4ms（R² +0.668）、排名精度 Spearman 0.813，4 码/3 码/2 键三档分别领先陈一凡 1986 群体两键表 35%/46%/51%（§5.3）；模型已贴实测噪声量级（§5.2）。⚠ 跨快照只比 MAE（测试集随数据增长整体重洗，R² 会跳 ±0.04 而 MAE 不动）。

> 本文档是**说明书**——只写**原理、实验方法、流程、结论**（当前的方法、口径、指标与复现方式）。**逐次实验的臂设计、读数、批间方向、产物漂移量与历史快照叙事不入本文**，存放于 `memory/keystroke-timing.md`（实验细节与决策史）与 `AGENTS.md`（运行时的铁律与注意事项）；文中数字以最新全链路重跑为准。三份文档的分工表见文末「相关项目与文档分工」。

**关键词**：击键动力学；条件当量；输入法编码评估；个人化建模；表格数据回归

## 1. 引言

键盘输入的时间成本模型是输入法编码方案评估与键位优化的基础。传统工具（Carpalx、KLA 类）以 **2 键当量表** B(a,b)——键对 (a,b) 的击键时间——逐对累加估算整串耗时：

```
T'(abcd) = B(a,b) + B(b,c) + B(c,d)
```

其隐含假设：键对间独立，打完一个键后手回静止起始位。该假设在两个层面失实：

1. **串中键对的前键从不是"空"**：打完 `r` 后手指停在 `r` 位，击打 `w` 的起点不是 home 位——相邻间隔互为条件、上一键准备完成后可直接启动下一键（Rumelhart & Norman 1982 的"间隔负相关"与"不回位"）。
2. **低估幅度按键对类型不均**：有前键的中段比空前键首段慢（跨手 +32ms、同手异指 +86ms，§5.4）——统一比例修正处理不了"同手段被低估更多"的结构性错位，编码方案排序被扭曲（约 20% 排序不一致）。

本项目以**对称条件段**为单位直接建模：段 `S(p,a,b,n)` = "前两键为 p,a 时击打键对 (a,b) 的按键时间（含后继键 n 的准备成本）"，总当量 = 段当量之和：

```
T(abcd) = S(∅,a,b,c) + S(a,b,c,d) + S(b,c,d,∅)
```

2 键表是段模型在空前键（∅）+ 无后继（∅）下的特例切片——2/3/4 键当量同源同尺度，完全自洽。

主要结果与贡献：

- **对称条件段模型**：前键条件效应 +31~+85ms 且按键对类型不均（§5.4）、后键条件化（φsuc7，v2 落地设计）——单一段表示统一 2/3/4 键当量
- **个人稳定期数据全链路**：2/3/4 键混采协议（欠样本加权、随机延迟去节律）、稳定期边界方法（自动剔练习漂移，§5.1）、B4b 两阶段残差异常剔除（§4.5）
- **部署混合模型 v7**（XGB + 神经分量固定种子平均，无选优噪声；段角色 φ35、嵌入 12）：固定 trial 测试集 T₄ 总时间 MAE 35.4ms / R² +0.668 / 4 码排名 Spearman 0.813，T₃ 留出 23.5ms、T₂ 15.6ms（§5.2），4 码/3 码/2 码三档分别领先陈一凡 1986 群体两键表 35%/46%/51%（§5.3）
- **段类条件错误率模型与段当量**：错误成本（错误率 × 实测错误修正时间，随采集动态更新）按段类计入，"当量"完整定义 = 按键时间 + 错误成本（§4.6-§4.7）
- **样本量终局**：模型已贴实测噪声量级（段组内 σ≈33.3ms，§5.2），专项扩容零收益

### 3.1 采集协议

`python 采集-按键时间和错误率.py`（tkinter GUI）：显示随机编码，录入真实击键时间戳。

**界面反馈（2026-10-08 用户要求：试次结束后只显示时间）**：屏上文字提示只给段时分解——**2 键 `xxms`、3 键 `xx+xx=xxms`、4 键 `xx+xx+xx=xxms`**（段时 = 按键间 delta ⇒ 等号右边是总时；取各段"显示值"之和以保证等式自洽，落盘仍写原精度）。打错时仍显示 `✗ 输入: …`（打字过程中已有 `✗ 期望 X` 即时提示），空格跳过显示 `␣ 已跳过`。

**2/3/4 键混采**：每试次按现行比例 **4 键 55% / 3 键 25% / 2 键 20%**（`P2, P3` = 0.20/0.25，§5.9）出码。2 键试次服务对称段模型的 **2键第1段** S(∅,a,b,∅) 测量——4 键试次的首段总带真后键，该"词首+词末"组合只能靠 2 键试次直接测量；3 键试次同理给出 3 键两个角色的直接测量（并让段位块的 `L==3` 维可辨识，§5.6）。**三档各用独立的欠样本键对池**（欠样本优先加权），行格式：2 键行 code 长度 2、c_d/d_d=0，3 键行 d_d/d_u=0，下游按 `len(code)` 分流。

| 操作 | 行为 |
|------|------|
| 输入显示的 2/3/4 个字符 | 正常打字 |
| 输错（任意键） | 立即变红停止，进入随机延迟 |
| 空格 | 跳过当前组（不记录），进入随机延迟 |
| Esc | 退出 |

**采样策略（多样性加权）**：首键均匀随机，后续键按 `w(b|a) ∝ 1/(n(a,b)+1)` 加权——欠样本键对优先（符号键 `;,./` 零样本时自动补足），键对样本量趋均衡后自动回归均匀随机。每次试次结束（正确/错误/跳过统一）延迟 **300-800ms 随机**再显示下一组，打断固定节律，防止"预期性击键"把键对难度差异压缩平均。

**输入法（2026-10-01，两个采集脚本同此）**：**无视输入法状态** —— 采集时不必切英文。修法两层，实现在共用模块 `采集输入层.py`：

| 层 | 调用 | 说明 |
|---|---|---|
| ③ 进程级 | `ImmDisableIME(0)` | **必须在建第一个顶层窗口之前**调用（MSDN 硬约束）⇒ 放在 `__main__`/`__init__` 建 `tk.Tk()` 之前。成功 ⇒ 本进程不加载输入法 |
| ② 窗口级 | `ImmAssociateContext(hwnd, NULL)` | 建窗后摘掉本窗口输入上下文；窗口激活时与每 2 s **重摘**（系统会重新关联） |

为什么必须处理：输入法中文态下，字母先被 IME 拿去组字 ⇒ tkinter 的 `<KeyPress>` 只带 `keysym='??'` / `char=''`，采集脚本读 `event.char` 会判定"没有按键"（**整场数据都收不到**）；IME 还会输出汉字、弹候选框。实测复现与两层效果见 `实验/实验-IME禁用验证.py`（真实注入按键：布局 `ImmIsIME=True` 的中文态下, 四键仍以干净 `char` 到达并正确落盘）。排障：`--no-ime` 关掉这两层（回到旧行为）。
（同源项目 `../并击击键当量/` 在此之上还有第三层**低层键盘钩子**——在 IME 之前就把键吞掉, 保证"输入法连键都看不到"; 串击实测 ②+③ 已足够, 故不引入全局钩子。**无全局钩子 ⇒ 事件源仍是 tkinter `<KeyPress>`、时间戳语义不变 ⇒ 已采数据与本文下面的全部口径不受影响**——改动只影响"中文态下收不到键"这一失效场景，英文态行为与改动前一致。）

| 字段 | 说明 |

## 4. 方法

### 4.1 问题定义

给定 4 字符编码 `abcd`，预测击键总时间 T（ms）。训练数据每行记录一个随机 4 字符串的实际击键时间戳。

### 4.2 对称条件段模型（v7 混合部署 · 段角色感知）

将序列拆成**段**（n 键码 → n−1 段），每段独立预测，条件 = **段角色 + 前两键 + 后继键**：

```
每段 t = MLP(e, φ35)   S(角色,p,a,b,n) ≈ MLP([e_p;e_a;e_b;φ35])   (71→128→64→1 + Dropout0.2; e ∈ ℝ¹²)
  双线性交互 3 项 e_pᵀW₁e_a + e_aᵀW₂e_b + e_pᵀW₃e_b **已于 2026-10-10 删除**（见 §4.4 ⑪）
  前键空/无后继 = 索引 30（∅）
  φ35 = 角色 5 + 跨键 30  ← **列序 v7 (2026-10-10 落地) 即三类序**: [存在(p), 存在(n), 码长==3, 码长==4, 段位==3]
        | φ8(a,b) 8 | φ8(prev,a) 8 | φ8(prev,b) 8 | bn 4 | an 2
        (内容 = 原 φ8 + φsuc7 + 角色块 3 + pa/pb 几何块 17 的重排: 数值逐位不变、纯置换,
         置换效应实测 ≤0.09ms 在噪声带内 ⇒ 判为「与效果无关」故采纳, 见 §4.4 ⑭;
         旧 `.pt` 由 `ord` 指纹拒绝。prev=∅ 时 pa/pb 块为 0。**只有一个存在位** —— pa/pb 的存在性恒等。依据 §5.8)
  三类视图 = 角色 5 [存在(p), 存在(n), 码长==3, 码长==4, 段位==3] / 键特征 0
           / 跨键特征 30 [ab8 pa8 pb8 bn4 an2]（原「学习型双线性 3」已于 10-10 删除）
  **展示序 = 实际张量列序 = 角色（p/n 存在 → 码长 → 段位）→ 键特征（时间侧无）→ 跨键（ab pa pb bn an）**
  （2026-10-10 晚先统一展示序；同日深夜按用户决策「列置换如果与效果无关就按照新的口径」
   把**实际列序也换成三类序** —— 置换实测在噪声带内 ⇒ 已落地, 见 §4.4 ⑭。）

段角色 (码长 L, 段位 i) — 等价的 6 类（**展示名 = 码长名+段位**；括号内是内部键名，
  旧称（角点/首段/短尾/中段/长尾）只在历史章节与快照引文里出现，见 §4.7）:
  L2i1 2键的第1段 S(∅,x,y,∅) · L3i1 / L4i1 3键的第1段 / 4键的第1段 S(∅,x,y,z)
  L3i2 3键的第2段 S(x,y,z,∅) · L4i2 4键的第2段 S(w,x,y,z) · L4i3 4键的第3段 S(x,y,z,∅)
  为什么必需: (p,a,b,n) 只编码「是否首段/是否末段」——3 键 seg2 与 4 键 seg3 签名相同
  ((有前键,无后键)) 却是不同角色, 单表无法表达 (与错误侧 09-19 段类重参数化同因)

部署混合 (BlendModel): S̄ = 0.3×XGBRegressor(独热122+φ35) + 0.7×mean_{s∈{0..4}} S_deep2(s)
  无选优环节 → 无选优抽签噪声 (决策带从 ±3 缩至仅测试重洗 ~±1ms), 同数据逐位确定

整串当量统一公式 (n 键序列 k₁k₂...kₙ; 首段前键=∅, 末段后键=∅):
  两键  T₂(xy)   = R(L2i1)[x,y]                                       ← 1 段 (2键第1段)
  三键  T₃(xyz)  = R(L3i1)[x,y,z] + R(L3i2)[x,y,z]                    ← 2 段
  四键  T₄(wxyz) = R(L4i1)[w,x,y] + R(L4i2)[w,x,y,z] + R(L4i3)[x,y,z] ← 3 段
```

### 4.3 模型结构

输入四元组 `(p, a, b, n)` 中三键 `(p,a,b)` 经**共享嵌入**与**交互部分**两条路径汇合后加 MLP 头，后键 `n` 经 φsuc7 特征进入 MLP（sym_phi 形式）。部署为混合（XGB 分量 + 神经分量×5 平均）。

```
输入: ids = [p, a, b, n]（31 索引, n 仅经 φ 生效）
φ35 的**实际张量列序** = 三类序（下表 §4.4）：[角色 5 | 跨键·ab 8 | pa 8 | pb 8 | bn 4 | an 2]
共享: e_p, e_a, e_b = E_key[ids[:, :3]]   E_key ∈ ℝ³¹ˣ¹²（30 键 + ∅；**v7: 20 → 12**）
```

**① 神经分量（deep2 v7，18,037 参数）**——键位嵌入 + φ 特征 + 深化 MLP：

```
S(角色,p,a,b,n) = MLP([e_p; e_a; e_b; φ35])        ← 双线性 3 项已于 2026-10-10 删除
```

| 组件 | 形状 | 说明 |
|------|------|------|
| E_key | 31×12 | 通用键位嵌入（p/a/b 三槽共享；n 不嵌入，只经 φsuc）；**v7: 20→12**（§4.4 ⑫） |
| MLP | 71→128→64→1 (ReLU+RMSNorm+Dropout0.2) | 非线性主体（含 φsuc 后键 + 角色块 + pa/pb 几何块）；dropout 使集成成员去相关、放大预测平均收益 |
| ~~W₁/W₂/W₃~~ | ~~3 × (20×20)~~ | **已删（2026-10-10）**：原为显式二阶交互（前键×首键、首键×次键、前键×次键），实测在现行 φ 体系下被 φ8(ab/pa/pb) 键对几何替代 ⇒ 删它省 1,200 参数且不亏（§4.4 ⑪） |

**② XGB 分量（确定性）**——XGBRegressor（500 树 / lr 0.06 / depth 6 / subsample 0.8 / colsample 0.8），设计矩阵 = 独热 **31+30+30+31 = 122** 维 + φ35 = **157 维**（**只有 prev/nxt 能取 ∅，a/b 恒为真实键故各 30 列**——2026-10-08 去掉两列恒零的 a槽∅/b槽∅，见 §4.4 编码说明）；种子稳定 ±0.18ms；自适应部分模式匹配（叶子 = 部分键模式 + φ 区间），对零样本组合外推同样有效（见过/未见三元组分组验证优势均匀）。

**③ 混合**：S̄ = 0.3×S_xgb + 0.7×mean(S_deep2, 成员集合)。**成员集合分两侧**：报表/评估 = 种子 0-4（五个，保住全部历史读数可比）；部署/产物 = 种子 0-29（三十个，压产物点值的种子抽签，§4.4 ⑲）。

**模型选型依据（09-14 当前数据全家族重跑，`实验/实验-架构对比{,2,3}.py`，原始 test 口径、神经 5 配对种子）**：全局最优 = 本混合 41.6ms / R²+0.592（对 ens5 −0.6、对单模最优 XGB −1.1、对神经单模 −2.4）。各类最优——**树系** XGB 42.7（单模最优，HistGBM 43.9 / RF 45.5 / ET 51.7）；**神经系** base 44.0（容量维 de32/dh128/再加深均持平 Δ≤0.2；结构删件全显著：no_w3 +2.6 / mlp_only +2.1 / bi_only +3.6 / 删φ +1.7）；**组合系** ens5 42.2。维持废弃：FT-Transformer 48.7（慢 ~12×）/ ResMLP 47.1 / 全局 FM 47.0 / 高斯秩目标 51.6 / 注意力聚合 47.4 / CP 张量分解 48.7 / 核方法 48.1 / kNN 70+ / ridge 49.0；目标函数 l1 / huber50 与 mse 已无差（±0.2）。

### 4.4 键位嵌入与几何特征

> **本节末尾是 ④–⑳ 共 17 条「设计-验证」结论一览表**（编号对应历史上的设计-验证记录；早期 ①–③ 条在脚本清理时已并入 §5.4/§5.8，编号故意保留不改——「§4.4 ⑰」这类引用在文档与 memory 里有数十处）。**表只给「改了什么 / 采纳还是否决 / 一句话依据」**；每条背后的臂设计、逐种子读数、批间方向、产物漂移量与存档文件名，见 `memory/keystroke-timing.md` 的「附录·README 迁出的实验细节」。**本表同时是「勿重测」清单**——已否决的方向不要重开。

键盘为 **3 行 10 列完整 QWERTY（30 键）**：26 字母 + `; , . /`。每键独立可学习向量 `e_k = E[k]`。当量定义：**期望键对耗时，单位 ms**（模型预测原始值，不做相对归一化）。

键位嵌入本身不含手指归属信息，故显式注入几何特征。**这些特征按「依赖哪些键」分三类（2026-10-10 重组，与错误侧 §4.6 同一套口径与命名：角色 / 键特征 / 跨键特征；跨键按 ab pa pb bn an）**：

**φ35 = 角色 5 + 键特征 0 + 跨键特征 30**（2026-10-10 删掉角色类里那 1 维严格冗余后，φ36 → φ35）

| 类别 | 归属 | 维 | 特征（列序即该族内部顺序） |
|------|------|----|------|
| **角色** | (码长 L, 段位 i) + p/n 是否存在 | **5** | 存在(p) · 存在(n) · 码长==3 · 码长==4 · 段位==3 |
| **键特征** | 键·p / 键·a / 键·b / 键·n | **0** | —（四槽的「键特征」就是身份本身，由共享嵌入 + 独热承载；**不存在"单键几何"**，故这一类在时间模型里为空） |
| **跨键特征** | 跨键·ab | 8 | 同手 · 同指 · 同键 · 列距 · 行距 · Fitts · 镜像手指 · 跨行同指 |
| | 跨键·pa | 8 | 同上 8 项 |
| | 跨键·pb | 8 | 同上 8 项 |
| | 跨键·bn | 4 | 同手(b,n) · 同指(b,n) · 同键(b,n) · Fitts(b,n) |
| | 跨键·an | 2 | 同手(a,n) · Fitts(a,n) |
| | ~~跨键（学习型）·ab / pa / pb~~ | ~~3 项~~ | **已删（2026-10-10）**：原为双线性 `e_pᵀW₁e_a + e_aᵀW₂e_b + e_pᵀW₃e_b`（秩 ≤20 的键对因子分解），实测被 φ8(ab/pa/pb) 的显式键对几何替代 ⇒ 见 §4.4 ⑪ |
| | 跨键（学习型）·bn / an / pn | 0 | 未加（bn/an 无证据；**pn 一律不加**：T₄ +0.01 / T₃ +1.26 纯负担——**其"存在性"已归入 角色**） |

**存在(p) / 存在(n) 为什么归「角色」而不是「键特征」**（2026-10-10 用户定）：两个位都是**位置信息**而非键属性——p=∅ ⟺ 首段、n=∅ ⟺ 末段，它们描述的是"这一段在码内的位置"，与 (码长, 段位) 同一性质。错误侧一直把「有后键」放在角色电平里（β），这样归后两侧口径完全对齐。

**每族用同一个 8 项定义函数**（代入各自的键对；键特征类为空是结构性的——各槽身份由共享嵌入+独热承载，只有能取 ∅ 的 p/n 需要存在位，而存在位已归角色）：

```
φ8(x,y) = [same_hand, same_finger, same_key, col_dist, row_dist, fitts,
           mirror_pair, cross_row_same_finger]

same_hand(x,y)  = 1  如果 x 和 y 在同一只手（左手=col 0-4，右手=col 5-9），否则 0
same_finger(x,y)= 1  如果 x 和 y 用同一根手指按下，否则 0
same_key(x,y)   = 1  x==y 同键重复（零幅移动需单独建模, 不适用 Fitts）
col_dist / row_dist  = |列差| / |行差|（İşeri & Ekşioğlu 2015: 列>行>手 重要性）
fitts(x,y)      = log2(1 + √(col² + (2·row)²))   Fitts 对数项, W=键宽, 行距≈2 键宽
mirror_pair(x,y)= 1  异手对称手指（Grudin 1983: 换位错误集中于镜像手指）
cross_row_same_finger(x,y) = 1  同指跨行（keygen: 同指顶↔底行最慢最易错）
```

**重组后看清的三个结构事实**：

1. **角色类的 6 维里有且只有 1 维严格冗余，已在 2026-10-10 删除（φ36 → φ35）**——**语义先定死：存在(p)=1 ⟺ 有前键 ⟺ 段位≥2**（p=∅ ⟺ 首段；故它不是"首段标志"）。于是 **存在(p) ≡ (段位==2) + (段位==3)**，**就是角色块两列之和**（精确恒等、连截距都不需要）⇒ 加上它**秩不变、信息不变**，是原 φ36 里唯一严格冗余的一列。反过来 **存在(n) 不可去**：存在(n) = 码长==3·(1−段位==2) + 码长==4·(1−段位==3)（即"非末段"，**含 2 键角点修正项**——角点段位虽为 1，其 n 同样是 ∅）——**乘积型，不在角色块张成内**（最小二乘投影残差非零，已在真实设计矩阵上验）⇒ 它恰好补上"加性块"缺的那一维（段位×码长交互方向）。秩的账：`{1, 段位==2, 段位==3, 码长==3, 码长==4}` 秩 5（对 6 个角色均值留 1 个约束），**并入 存在(n) 后秩 6 = 满秩 ⇒ 角色均值可自由拟合（饱和）**。既然两个存在位都保留，则段位那一对只能留一个（**`段位==2 ≡ 存在(p) − 段位==3`**，对称式亦然）⇒ **落地形式 = 角色类 5 维 {存在(p), 存在(n), 码长==3, 码长==4, 段位==3}**：对 6 个角色两两可分辨且秩 6 = **最小饱和参数化**（原 6 维是"饱和但含 1 冗余列"：7 列装 6 维；现 5 维是 6 列装 6 维）。⚠ **本块单独不再两两可分辨**（L3i1/L3i2 与 L4i1/L4i2 各撞码），可分辨性来自与两个存在位的组合。⚠ 方法学教训：这类"严格共线"的断言**不能靠语义直觉下**——本轮把 存在(p) 的方向读反了两次（先写 `1−(段位==2)−(段位==3)`、再写 `(码长==3)+(码长==4)−(段位==2)−(段位==3)`），两次都被**真实设计矩阵的逐元素 max\|Δ\| 比对**（=1.0）当场抓出；凡恒等式断言必须落到"在真实矩阵上逐元素验证"这一步。推导、秩表、五臂实测与落地漂移见 §4.4 ⑥ 与 ⑦。
2. **存在位归角色（而非键特征）**：两个位都是位置信息（p=∅ ⟺ 首段、n=∅ ⟺ 末段），与 (码长, 段位) 同一性质；错误侧一直把「有后键」放在角色电平里（β），这样归后两侧口径完全对齐。
3. **各族完备度不对称**：ab / pa / pb 取全 8 项，而 bn 只 4 项、an 只 2 项（φsuc 起源）。历史上测过把 bn/an 扩到全 8 ⇒ **an 去掉全 8 反而更好（T₄ −0.19）、bn 打平（+0.02）**；现状子集内 6 维逐维 LOO 全为正（bn 最承重的是 Fitts）⇒ **一维都删不掉，维持现状**（详表 §5.8）。

⚠ **本表既是分类，也是 φ35 的**实际张量列序**（2026-10-10 深夜起, 见 §4.4 ⑭）**：设计矩阵按 `[角色 5: 存在(p), 存在(n), 码长==3, 码长==4, 段位==3 | 跨键·ab 8 | 跨键·pa 8 | 跨键·pb 8 | 跨键·bn 4 | 跨键·an 2]` 拼接。此前是历史叠加序 `[ab8 | 存在(n) | bn4 | an2 | 角色块3 | 存在(p) | pa8 | pb8]`，两者互为**纯置换**（脚本内逐列断言 35/35）；置换实测在噪声带内故采纳，且 `BlendModel` 写入 `ord` 指纹拒绝旧序权重。XGB 侧消融用的块名与三类的对应关系（v7 下这些块**不再连续**，`实验-XGB几何消融.py` 已改用索引列表）：`ab8` = 跨键·ab 全部 8 项（v7: 5..12）；`suc7` = 存在(n) 1 + 跨键·bn 4 + 跨键·an 2（v7: [1]+29..34）；`role3` = 角色里的 码长==3/码长==4/段位==3（v7: 2..4）；`papb17` = 存在(p) 1 + 跨键·pa 8 + 跨键·pb 8（v7: [0]+13..28）（见 §4.9 的 XGB 侧几何消融）。

**消融结论**：逐特征 leave-one-out 全部持平（特征互为冗余），但整体删除损失 +1.7ms、角点 +3.2ms（09-14 当前数据复测，与 08-14 原测同值）——φ 作为整体提供嵌入补不上的几何先验，价值在稀疏三元组外推（2/3 按键时间表条目零样本）。手工指对类别编码（独热）与键嵌入+双线性等价（嵌入本身即更细的键对类别表示）；生理学导向改造（指距替代列距等）经两轮独立批实验全部关闭，φ8 维持。

**键位编码（XGB 分量）**：4 个槽位 (p,a,b,n) 用**各自基数的独热**——`prev` 31 列、`a` 30 列、`b` 30 列、`nxt` 31 列（30 键 + ∅），合计 **122 列** + φ35 = **157 维**。**为什么各槽基数不同**：只有 `prev`/`nxt` 能取 ∅（首段无前键、末段无后继键，实测各 7336/17292 段为 ∅），**`a`、`b` 是实际按下的两键、恒为真实键**（调用点保证）⇒ 各只需 30 列。

> **2026-10-08 修正（去死列 124→122）**：原实现四槽一律 31 列，多出的 a槽∅ / b槽∅ 两列**全数据恒 0**（实测 0/17292 非零）、从未参与分裂（XGB gain 报告里完全没有这两列，模型实际只用到 158/160 列）。修正后**受控对比**（同训练池/同测试集/同超参）：测试段MAE 22.83 → 22.83、测试总MAE 35.10 → 35.11（差 0.01ms = `colsample_bytree=0.8` 的抽样落点，非系统性）；训练 1.3s → 1.1s；产物漂移码级 |Δ| 中位 0.28–1.30ms、ρ 0.9990–0.9995、系统性偏移占方差 0.0%。**结论：压缩是"零收益的清理"**——不买精度，只去掉编码不可能的取值（也让设计矩阵能自洽解释）。⚠ 列布局变了 ⇒ 旧 `按键时间模型-xgb.json` 不兼容，`BlendModel.save` 写入 `dm=122` 指纹、`load` 校验并报错（避免静默错用）。
> **为什么不再压（评估过的替代方案）**：① **原生 category**（`enable_categorical=True`，4 列替代 124 列）实测**更差**——测试段MAE 22.83 → 23.37、总MAE 35.10 → 36.11（partition 分裂在本数据上不如 one-hot 的轴平行切分）；② **序数编码**（1 列整数）会给树引入虚假的键位顺序，是标准禁忌；③ **目标/影响编码**在 900 键对的稀疏格上有泄漏风险且此处无必要。**一般做法判断**：低基数类别（此处 30）用 one-hot 是 GBDT 的常规选择，XGBoost ≥1.6 虽支持原生类别但官方也提示高基数下才明显有利——本项目实测维持 one-hot（122 列）。

### 4.5 训练协议

- **目标**：批量 MSE（段级），验证集 20%，早停 patience=60，Adam lr=0.001
- **训练形态（无选优）**：固定种子训练若干神经分量取**预测平均**，与确定性 XGB 混合部署（权 0.3/0.7）——同数据逐位可复现。**成员集合分两侧（2026-10-12 用户决策「生产部署成员数改成 30」）**：报表/评估 = `BlendModel.SEEDS`（0-4，五个，保住全部历史读数可比），部署/产物 = `DEPLOY_SEEDS`（0-29，三十个，压产物点值的种子抽签 = 单条 T₄ 查询 5.5→2.2ms；只改部署侧 ⇒ 不动任何报表指标，见 §4.4 ⑲①）。选优环节（best-of-N）曾引入 ±2ms 抽签噪声（验证最优候选可为测试最差），已移除
- **可复现性与并行**：模块导入即固定运行环境（单线程+播种）；训练成员构造显式种子化 → 每成员 = (seed, 数据) 纯函数，全流程多达 40+ 次训练经 spawn Pool 并行（多核 `--full` 约 6m30s；2026-10-12 部署成员 5→30 前为 3m33s），`KJ_SEQ=1` 强制串行；并行/串行产物逐位一致
- **验证集泄漏**：同一 trial 的三段共享个人速度因子（trial ICC 0.308），段级随机划分使验证集系统性乐观 ~9ms——**模型对比与报告口径必须用 trial 级留出**（§5.1）
- **异常剔除（B4b 两阶段残差，键对分桶）**：
  - **数据准入**：唯一数据源 `数据/击键测速数据.tsv`，**error=0 才入**，段时严格递增校验（4 键 b_d<c_d<d_d / 3 键 b_d<c_d）；**段时 = 按键间 delta**：首段 b_d，中段 c_d−b_d，尾段 d_d−c_d
  1. 段位分桶 MAD k=3 剔除 → 训练 M0（干净模型提供"期望行为"）
  2. M0 推全数据 → 带符号残差 `y−ŷ`（正 = 比预期慢）
  3. 残差按**键对 (a,b) 分桶**、**单侧上围栏**（r ≥ med + 3·1.4826·MAD）剔除——只删"比该键对合理预期慢"的段（注意力中断只拖慢不加快；偏快是 rollover/预备连击的真实行为不删）。剔除率随池变化（当前稳定期池实测 ~2.7%，早期快照 ~4.8%；van Selst & Jolicoeur 1994 调研范围 5-10% 内）
  - 依据：全局残差法会把"模型学不会的难键对"的真实慢段当异常删（用模型偏见定义正常，循环论证）；键对分桶修复当量失真。剔除收益在**当量稳健性**而非预测精度（无剔除与 B4b 的测试 MAE 在噪声内）。**测试集需用独立剔除（固定流可复现）**
  - **剔除单位 = 整 trial（2026-10-08 用户决策）**：一个 trial 内任何一段超 MAD/键对围栏 ⇒ **整条 trial 不入训、不入评**（含错 trial 那条在数据准入就已整体排除）。依据：**段模型带 4 键上下文**，同 trial 的段共享该 trial 的速度状态与上下文，某段被判异常时其余段很可能同样被污染——逐段剔除会把"半污染 trial"的残段喂给模型。落地：新增 `trialwise_keep()`（逐段掩码 → 整 trial 掩码），**第 1 阶段 M0 的训练集与第 2 阶段判定都升级**；`KJ_TRIALWISE=0` 回退逐段口径（仅供复现历史数字/受控对比）。**影响实测**：逐段口径下训练池有 470/7854 trial 属"被剔段但其余段仍入训"（占保留段 4.8%），整 trial 口径下训练池 18261→**17292 段 / 7336 trial**、部署池 22854→**21715 段**。**副产品：两层指标的关系变成精确恒等**——段级 n = 段数 × 总级 n（T₄ 3390 = 3×1130、T₃ 408 = 2×204），总级偏差 ≡ 段数 × 段级偏差。
  - 原「整 trial 级排除」只有稳定期边界（§5.1：按 150-trial 块切、整 trial 剔除练习漂移期）；⚠ 训练内部的 80/20 验证集划分仍是**段级**随机（已知泄漏 ~9ms，故报告口径一律用 trial 级留出）。
- 段样本：每 trial 3 段（t₁: 空→ab, t₂: a→bc, t₃: b→cd），共享 MLP 头，段间互相增强

### 4.6 键对错误率模型与错误修正时间实测

一次按键错误的代价与键对运动难度解耦——错误成本（错误率 × 错误修正时间）按段自身键对、按段角色条件计入（实证 §5.5）。两个数据源：

**① 错误率 P_err（`分析-错误率.py`，全量数据）**：

模型与时间侧**同格式** `(p, a, b, n)` 条件化，设计 = **19 列**，按「键特征 / 跨键特征 / 角色」三类组织（与 §4.4 时间侧同一套口径与命名；跨键顺序统一 `ab pa pb bn an`）：

| 类 | 分组 | 列数 | 具体列 |
|---|---|---|---|
| **键特征**（单键函数） | 键·p / 键·a / **键·b** / 键·n | 0 / 0 / **4** / 0 | b左小指 · b顶行 · b底行 · **食指(b)** |
| **跨键特征**（键对函数） | 跨键·ab | 5 | 同手 · 同指 · 同键 · 小指-无名 · 小指-食指 |
| | 跨键·pa | 2 | 同键(p,a) · 同手(p,a) |
| | 跨键·pb | 0 | —（时间侧有效 ≠ 错误侧有效：全 8 项 ΔAUC +0.00006） |
| | 跨键·bn | 2 | 同键(b,n) · Fitts(b,n) |
| | 跨键·an | 2 | 同手(a,n) · Fitts(a,n) |
| **角色** | — | 3 | 有后键 β · 段位−1 δ · λ 3键首段 |

**角色电平 = 6 个段角色由 3 参数给出**（L2i1=0 / L3i1=β+λ / L4i1=β / L3i2=δ / L4i2=β+δ / L4i3=2δ）——**纯加法，无交互项**。段类 = **(有前键, 有后键, 段位)**，5 类（由 码长×段位 映射；2026-09-19 重参数化，取代旧 (有无前键, 有无后键) 四列签名）。**为什么重参数化**：旧签名在**仅 2/4 键数据**上与 (码长, 段位) 一一对应（无损、当时看不出来）；加入 3 键后「尾段」被劈为 c2（3键第2段）与 c4（4键第3段），旧模型显著拟合不足（D=8.87, p=0.012 复核），新五类充分（D=1.31, p=0.52）。同时**「有前键」不再单列**（观测里 有前键 ⟺ 段位≥2 完全共线，旧 α=+2.10 实为位置效应，引入段位后塌缩到 0）。段类的物理含义 = **起始保护**（2键第1段 ≪ 首段）· **末位保护**（同段位下无后键更低，β>0）· **码内累积负担**（无后键三格随段位爬升，δ）。

**交互项 γ 已删（2026-09-21 用户决策）**：γ(有后键×段位) 在重参数化后的口径下历次不显著（−0.10±0.17），而判定它需 ≈638,000 trial、点估计 ≈0；删掉换 2 个自由度后 **β 的 SE 从 0.270 降到 0.125**（γ 与 β 共线，去掉约束那份信息回到 β）。做「删得对不对」的**常设监控**：`分析-错误率.py` 每次运行并排拟合一次带 γ 的版本并报 D/p（形式不被数据拒绝）。

**当前拟合（10-11 晚刷，50461 键对事件 / 932 错误 = 1.85%）**：β=+0.318±0.107 (z=2.98) / δ=+0.823±0.072 (z=11.50) / λ=−0.098 (p=0.63) / 食指(b)=−0.187 (z=−4.99，保护方向)；六角色 O/E = 0.76/1.00/1.17/1.01/1.00/0.99（全在 Poisson 带内）；监控① γ D=0.032 p=0.857、监控② 角色电平饱和 D=2.683 p=0.261；片均值 P_err 0.68/0.92/1.78/0.91/2.15/3.14%。

**部署模型 = XGB（2026-10-11 用户决策「现在就部署树模型」）**：19 列逻辑回归降为**监控伴模型**（系数读数 / 监控①② / 特征审计照常运行，不进产物）。树侧实测：同特征 XGB 只 +0.0016，但 **+ 四槽身份独热 122 列（d3）得 +0.0062 AUC（t=+3.23，两批同号）**——**增益全部来自键身份**（逻辑回归因 EPV≈29 装不下身份；树的结构化正则装得下，与时间侧「树吃全身份」同一机制）；折外校准也不差（3键第2段 L3i2 0.95 vs LR 1.16）。导出 **`产物/错误率表.npz`（v2，6 角色片）**；每刷重算的折外监控：AUC 0.7362 / O/E 0.71~1.05。

**事件口径**：2/3/4 键行全入模；错误 trial 在错键截断——错键对只记 err、其前的键对记 ok、首键即错不记事件（键对未尝试）。

**特征集的来历（结论；逐次消融读数见 memory）**：**2026-10-07 用户决策「删掉自动选型、固定基线」**——选型差历次 ≤0.002 全在折间噪声内，但旧 `>=` 规则让选型随数据翻转、把产物推着走；此后只有经「消融 + 两独立批复核」验证过的项才增补。同批落地 **小指-食指**（保护方向，两批独立数据同号、48 场中 38 场同向）与**同指块重参数化**（`同指 = 同键 + 同指同列 + 同指双列` 恒成立 ⇒ 取 `{同指, 同键}` 为基）。**10-10 落地食指(b)**（LRT D=18.5, p=1.7e-05；效应就是「食指」本身，不是频次代理）与**删 3 列冗余**（无名-中指 / bn·同手(b,n) / bn·同指(b,n)：单列不显著 **且**整组也不显著 **且** 校准逐位不动）。13 特征 AUC 只作**报不选**的监控。

**② 错误修正时间 cost（`采集-错误修正时间.py` + `分析-错误修正时间.py`）**：连续长随机串（120-200 字母）+ 自然回退纠错，单框逐字符着色（白=未打/绿=对/红=错）——错误发现以立即型为主，对应短码语境。测量"**首错按下 → 首错位置打对**"的净耗时（反事实世界尾段同节奏平移，原始区间即净成本）；连锁错（含同位二次错）吸收为单事件——错误只计首错、时长只记首错间隔；episode 判定在采集端实时完成，只落盘错误键事件与串汇总（`数据/错误修正时间-错误键.tsv`）。

**时长异常剔除（分析端）**：过程分桶（发现型 imm × 退格数档）桶内单侧 med+3×1.4826×MAD 围栏——语义同 S 模型剔除（注意力中断只拖慢不加快，只删过大侧）；退格/盲打是时长的过程簿记结构（+~400ms/退格、+~350ms/盲打字母）**必须分桶**，否则误删合法的连锁/盲打长纠正；桶 n<8 不设栏（保守）；剔除只作用于时长统计，事件计数与率仍用全部闭合 episode。

**当前实测**（282 事件 / 22959 按键 / 12 有效坐姿，弃首坐姿+围栏剔 4 后 n=278）：全体 782ms（SE 15）/ 立即发现 701ms（n=212）/ 延迟发现 1042ms（n=66）。双成分结构：延迟 = 立即 + 过程增量（回归截距与立即均值差 +4ms 定量成立）。**该数据源 2026-09-13 起停更**（cost 定案欠账见 §5.7）。

**定案机制**：续采监控，三判据全满足即冻结 cost——①簇稳健 SE≤30ms（均值位置钉住，T₄ 传导 <±2ms）②近 10 坐姿斜率不显著（近端窗口）③近 5 坐姿均值与全体差 <40ms；监控规则：单次刷新均值变动 >±75ms（2×簇SE）回查。**现值 ① 29ms ✓ / ② t=−2.52 ✗ / ③ 差 −72ms ✗，约束项 = ③**（② 会随窗口自然转好，③ 是平台检验——需坐姿均值走平，只差 +278 episode；测算见 §5.7）。cost 为乘法标量，对优化排名零影响、只定绝对刻度。导出 `产物/错误修正时间-实测值.txt`（label 行式：cost_ms 数据行 + 手别诊断行——左/右手目标纠错差 +69ms（t=4.1，同手纠错串惩罚，退格位依赖的布局结构），为当量表通用性不入表）。


### 4.7 段当量与产物链

错误率模型与按键时间模型合并，构成本项目标准产物链（`组装当量表.py`）：

```
段当量 = 按键时间 S(段角色,…) + 错误率 P_err(段角色, p,a,b,n) × 错误修正时间 cost
                                                                  → 产物/段当量表.npz（按段角色 6 个切片, version 6）
  cost = 错误修正时间实测标量 (产物/错误修正时间-实测值.txt, 分析-错误修正时间.py 导出, 随采集动态更新)

  ⚠ 两侧现为同构表（段角色 6 片），组装 = 逐片直接相加（不再需要把 (a,b) 错误率广播到角色维）
总当量（2/3/4 键当量）= 段当量求和:                                            → 产物/总当量-2-4键.txt
  T₂(xy)   = seg_L2i1(xy)
  T₃(xyz)  = seg_L3i1(xyz) + seg_L3i2(xyz)
  T₄(wxyz) = seg_L4i1(wxy) + seg_L4i2(wxyz) + seg_L4i3(xyz)
```

**产物七件**：模型双文件（`按键时间模型-神经.pt` / `按键时间模型-xgb.json`）+ `按键时间表.npz`（v3, 6 角色片）+ **`错误率表.npz`（v2, 6 角色片；2026-10-10 起取代 键对错误率表.txt，2026-10-11 起部署段为 XGB）** + `错误修正时间-实测值.txt` + `段当量表.npz`（v6）+ `总当量-2-4键.txt`。**组装自检**：主流程与组装脚本都会打印 `T₂/T₃/T₄` 三档总当量参考值，用于抓「表被喂错特征/错序」这类静默错误（v7 落地时正是靠它抓到 φ 行内拼接漏改）。

### 4.8 设计边界

- ❌ **字母 N-gram 频率**：不引入自然语言熟悉度偏差，纯随机采样
- ❌ **连组模式**：每组独立开始（模拟分词间自然停顿），不建模组间转移
- ❌ **节奏/节拍器**：随机延迟打断节律，按"打对条件下尽可能快"测试
- ❌ **变长编码**：仅测 2/3/4 字符编码（其它码长不采样；4 码内是应用域上限，§4.8 末条）
- 🎯 **应用域 = 4 码内**：当量的优化与使用仅限 4 码内词内评估（主要 4 码二字词，词间自然分词间隔）——孤立 4 键试次的范式与真实词内输入结构一致；跨词连续序列不在建模范围

## 5. 结果

### 5.1 评估口径

**跨快照 / 跨人的量纲问题与相对误差**（2026-10-10 用户提问「MAE 算的是绝对时间差，但段按键时间本身有练习效应、随样本数增加而减小，所以 MAE 跨时间不可比；不同人的绝对大小也不同，能否用相对差衡量」；`实验/实验-相对误差口径评估.py`）：**前提成立** —— 本数据 4 键 trial 按时间序 150/块的中位 **首 457 → 末 334ms（跨度 −26.8%，全序列 321~538ms）**，⇒ 同一个 20ms 的 MAE 在慢端是 3.7%、在快端是 6.2%（**差 1.67 倍**），跨期确不可比；跨人同理。**但直接把主指标换成相对量 `nMAE = MAE / mean(y)` 也不行**：实测**误差远非比例型** —— 测试段按实测时间分十分位，层间水平跨 **5.72 倍**（39.5 → 226.1ms），而 MAE 只跨约 2 倍且非单调（常规段 60–190ms 内 MAE 仅 15~23ms）⇒ **存在明显的固定误差底**；于是 `nMAE = a/y + b` 会**随打得更快而机械上升**（把「人变快」读成「模型变差」），偏差方向与绝对 MAE 恰好相反。**故采用三层报法（2026-10-10 用户指令已落地）**：
① **主指标仍是绝对 MAE**（同一快照内比较）—— 决策带 ±3ms、重洗带 ±1ms、偏差 SE 全部标定在绝对量纲上，换主指标属口径变更，历史阈值与快照会一并失效；
② **并列报 `nMAE`（%）作为跨期/跨人可比层**（**已落地：三档报表与陈表三档对比均并列输出 mean 与 nMAE**）—— 零成本，且让三档可比：当前 **T₄ 总 10.03%（段 19.12%）/ T₃ 11.31%（段 19.83%）/ T₂ 19.35%**，即绝对量最小的 T₂（15.6ms）在相对量上反而是**最难的一档**（2键第1段只 80.5ms 长，同样 15.6ms 误差占 19%）；分角色看 nMAE 的跨度远小于绝对 MAE 的跨度 ⇒ 相对量是更对齐的视图；
③ **跨快照务必连 `mean(y)` 一起报**（否则相对量无法回填 —— 历史快照大多没记分母）；跨人时把分母换成**该人自己的 mean(y)**，并并列报 **scale 不变的 `min_k MAE(k·p, y)`**（即对陈表已在用的 ×k 机制，回答「形状是否可迁移」—— 项目已有证据说明**尺度结构不可迁移**：陈表三档 ×k 86.1 / 59.5 相差悬殊）与 **`MAE/σ(y)`**。
⚠ 另测一条：把误差分解为「固定底 + 比例项」（`MAE ≈ a + b·y`）**对分层方式不稳健**（十分位给 12.4ms + 5.1%·y，按 6 角色给 −2.8ms + 22.2%·y 二者不一致）⇒ 该分解只能作「看形状」的辅助诊断，**不可当可移植定律**。

### 5.2 主精度（三档统一报表）

**偏差 (bias) 的定义（2026-10-08 起全项目唯一约定，三档共用）**：

> **偏差 = 预测 − 实测**（ms）。负 = 模型低估（预测比实测快），正 = 模型高估。
> 另有**段位偏差** = 该段角色上（预测段时长 − 实测段时长）的均值，以及**段级偏差**（全部段样本）。
> 段时 = 按键间 delta ⇒ **总级偏差 = 同一 trial 内段级偏差之和**（三段之和对 4 键即 T₄）。
> SE 一律取该层误差的 SD/√n（ddof=1），z = 偏差/SE。

⚠ 两处易混、**勿改**：① B4b 剔除**内部**残差反号（`r = 实测 − 预测`，正 = 比预期慢）——那是单侧上围栏的过滤判据，与报表偏差是两回事；② T₂ 在 2026-10-08 之前按 `实测 − 预测` 报（与 T₃/T₄ 反号），同日统一为本定义 ⇒ **历史文档/快照里的 T₂ 偏差值须取反**后与本表比较（幅值不变）。

| **条件段模型（2键的第1段 L2i1）** | 本征 ms | **15.6ms** | 12.0 | **0.684** |
| 陈一凡表 | ×k₂=58.5 | 31.6ms | 22.2 | 0.523 |

**[3] 3 码累加**（保留口径完整 trial，n=440）：

| 方法 | ×k₃ | scale 后 MAE | scale 后 R² | 排名 Spearman |
|------|-----|-------------|------------|--------------|
| **条件段模型（T₃ = 两段和）** | **1.003** | **23.6ms** | **+0.773** | **0.879** |
| 陈一凡累加（逐对求和） | 74.4 | 43.4ms | +0.345 | 0.530 |

结论：

1. **4 码：条件模型领先 ~35% MAE、排名 0.813 vs 0.554**，绝对标定近完美（×k₄=1.014 vs 陈表需 ×85 对齐个人速度）
2. **2 码：个人 2键第1段 15.6ms 大胜陈表 31.6ms（领先 51%）**——键对级难度由个体差异主导，个人小样本胜过群体大数据
3. **3 码：领先 ~46% MAE、排名 0.879 vs 0.530**，标定 ×k₃=1.003 —— 与 4 码同源的累加对比；三档排名精度 0.684（2 码）→ **0.879**（3 码）→ 0.813（4 码），**2 码最低（其 2键第1段 片池最小，仅 611 trial）**
4. **陈表三档缩放系数不同**（×k₄=84.6 / ×k₃=74.4 / ×k₂=58.5）——群体表与本人在不同码长语境的尺度结构不一致，印证不同被试的绝对当量水平与难度结构均不可迁移（这正是"条件段模型"存在的理由）

### 5.4 前键条件的实证依据

段间隔按**键对类型 × 前键条件**分解（10-11 晚刷重算：部署按键时间表口径；量级与方向和早期全量口径一致）：

| 类型 | 空前（首段） | 有前键（中段） | 差 |
|------|------------|--------------|-----|
| 跨手 | 72ms | 104ms | **+32ms** |
| 同手异指 | 64ms | 149ms | **+85ms** |
| 同键重复 | 147ms | 155ms | +7ms |
| 同指异键 | 192ms | 199ms | +7ms |
| **混合平均** | **73ms** | **125ms** | **+52ms** |

所有类型的方向一致（有前键更慢——手打完上一键不回位），但**幅度按类型不均**（跨手 +32 到同手异指 +85ms）。这正是 2 键表不可修的原因：统一比例放大修不了"同手段被低估得更多"的结构性错位（实证见 §5.3；两键累加与条件模型在随机 4 键码上 20.1% 码对排序不一致——Spearman 0.809，且两键累加对 100% 的码低估）。

模型视角（当前部署按键时间表 S(∅,x,y) vs 平均 S(p,x,y)）：跨手 `fi` +35ms、同手异指 `wv` **+109ms**、同指同列 `az` +16ms、同键 `aa` +1ms——同手连续是前键条件最敏感的类型。

### 5.5 错误率结构实证

**段类条件的依据**：错误率随码内位置强烈爬升（段位 1 的 0.41%/0.90% → 段位 3 的 3.18%；2 键码是"没爬起来就结束"的短爆发，故 2键的第1段最安全），无上下文模型把位置平均掉——**类盲模型对 T₂ 条目高估 10.3ms/条目**（高错误键对前 10% 达 23.0ms），且偏差与 P_err 成正比会扭曲 2 键简码排序。部署差异（类盲 → 段角色，当前数据）：错误成本 T₂ 14.5 → **4.5** / T₃ 29.1 → **17.5** / T₄ 43.6 → **48.5ms**（T₄ 反向是因为段角色把 4键第3段 格单独抬高）。

**段类重参数化的读数**（2026-09-19 落地，取代旧四列签名）：3 键数据暴露了旧签名的错分——3 键码的第二段（3键第2段）与 4 键码的第三段（4键第3段）共用一列，实测 1.20% vs 3.11%（p=0.005），组装期 T₃ 错误项因此**系统性高估 15.7ms/码**。重参数化后 T₃ 平均 **−15.7ms**、T₂ +0.23（角点列校准更贴实测）、T₄ −0.4；复核：旧四类始终不足（D=8.87, p=0.012）、部署五类始终充分（D=1.31, p=0.52）。

**结构命门**：错误率与「中断段率」是**两套不同结构，不能互套**（中断率与错误率在码内位置的形状不同：错误率单调爬坡，中断率首段高发；中断率的键对结构也弱得多）⇒ 本项目**不给中断单独建模**（§5.1 保留口径的基石假设：中断率是会话状态变量，不是键位属性）。

**键对难度参考**（稳定期 B4b 段中位）：跨手 91ms < 同手异指 112ms < 同键重复 151ms < 同指异键 196ms。

**错误率侧特征空间的结论**：**在「先验列候选」（19 项全消融 + 6 键对块 + 身份独热 + 角色饱和 + 镜像/连续几何）与「结果数据驱动挖掘」两条路径上均已关闭**——后者用部署同款 XGB 的折外残差 × 14 条「模型之外」属性做富集扫描，再用 2000 次按格置换的家族最大 |z| 作多重比较闸门，实测**全部不过闸门（最大 |z| 2.03 < 原分布中位 2.28）**。再开只能靠**新数据源 / 新测量维度**，不是现有结果数据的再加工。逐项读数见 `memory/keystroke-timing.md`。

### 5.8 pa/pb 几何特征落地（φ19 → φ36，2026-10-07 用户决策）

| pn | T₄ +0.01 / T₃ +1.26 | **纯负担，不加** |

**效果（受控口径：同一 B4b 掩码、同一测试集、同一固定 5 种子）**：T₄ 总MAE 36.18 → **35.35（−0.83）**、T₃ 29.78 → **26.37（−3.40）**、验证段 21.96 → 21.40。**两独立种子批同号**（批 B T₄ −0.40 / T₃ −3.47）。**T₃ 的收益远大于 T₄**，机制上说得通：3 键的 seg2 拿到 `φ8(x,z)`（它的唯一盲区对），而 3 键角色数据稀疏 ⇒ **显式几何先验在稀疏处的边际价值最大**（与「φ 的价值在稀疏三元组外推」一致）。

**同时被证伪的两条路（记录备查，避免重走）**：① 把同样的盲区 φ8 并进**特征通道**无效（且伤 T₃）；② 在训练损失里加**总时项**（`段MSE + λ·总时MSE`）单调变差；③ 事后在总时上挂 φ8 线性修正项有效（两批同号）**但无法结构化落地** ⇒ **本次真正落地的收益来自特征扩展这条第三条路**。落地时新增 `KJ_GEO=0` 开关退化旧配置 φ19 —— **逐位复现旧快照**，作为「改动在关闭时不改变任何行为」的强制自检。

### 5.9 新用户采集需求估算（2026-10-11 用户提问「估计新用户按什么比例采、共需多少样本」）

**问题**：§5.7 回答的是「现用户还差多少」（逐项欠账），与「新用户从零开始要采多少」是两件事——新用户没有可借的历史，六片全部要从零建立、且必须先付练习期。工具 `实验/实验-新用户采集需求.py`（时间侧）+ `实验/实验-新用户错误侧曲线.py`（错误侧），输出存档 `实验/_新用户采集需求-输出.txt`、`实验/_新用户采集需求-错误侧-输出.txt`。

**方法**：现用户的稳定池按比例抽样当训练集，**完全复用管线口径**（`stable_pools`/`build_tensors`/`residual_filter_segments`/`BlendModel.fit`/`bias_triplet`），在**固定测试集**上评（管线 seed-2024 留出；其 B4b 掩码只依赖测试集自身、与训练量无关 ⇒ 各点可比）。**f=1.0 自检逐位对齐现行快照**（T₄ 35.3 / T₃ 23.8 / T₂ 15.4 vs 报表 35.4 / 23.5 / 15.6）⇒ 脚手架可信。这是「同一人的数据量→精度」曲线，作为新用户的**样本量代理**（新用户重学同一任务，所需样本量按此估）。

**A. 时间侧联合学习曲线**（三码长同比例抽样，保持池比例 56/19/25）：

| 总 stable trial | 481 | 964 | 1931 | 3863 | 6760 | 9659 |
|---|---|---|---|---|---|---|
| T₄ 总MAE | 41.58 | 40.33 | 37.55 | 36.19 | 35.49 | 35.29 |
| T₃ 总MAE | 29.80 | 27.20 | 25.78 | 24.59 | 24.51 | 23.84 |
| T₂ MAE | 18.34 | 17.74 | 16.05 | 16.24 | 16.00 | 15.43 |

**20 倍数据只买 ~6ms**（T₄ 41.6→35.3）——与 §5.2「精度天花板」一致。**拐点在总 ~4000 stable trial**：此后每翻倍 T₄ 只再降 0.70 / 0.20ms。逐段增益（T₄）**+1.26 / +2.77 / +1.37 / +0.70 / +0.20** ⇒ 收益最深的一段是 964→1931（+1931 到 ~2000）。按码长看拐点：**4 键 ~3800 stable trial 后平坦；3 键 ≥1800 仍在缓降；2 键 ~500–1000 即饱和**。

**B. 配比扫描**（固定总训练量 6000 trial，各配比 × 2 抽样种子）：

| 配比 (2/3/4 键%) | n4/n3/n2 | T₄ | T₃ | T₂ | 相对候选A |
|---|---|---|---|---|---|
| 候选A **20/25/55** | 3300/1500/1200 | 35.58 | 23.96 | 15.79 | — |
| 候选B 15/25/60 | 3600/1500/900 | 35.45 | 23.91 | 15.69 | −0.13/−0.05/−0.10 |
| 候选C 25/30/45 | 2700/1800/1500 | 35.89 | 23.81 | 15.55 | +0.32/−0.15/−0.24 |

**结论：配比不敏感**——配比间的 MAE 差异（≤0.32ms）与**抽样种子噪声同量级**（同配比换种子，T₄ 摆 0.23–0.32ms：候选B 两种子 35.29 / 35.61）。故 **2键 15–25% / 3键 25–30% / 4键 45–60% 区间内任取皆可**；4 键略优（T₄ 是主指标、含 3 个角色片、且错误事件最便宜 6.2%/trial）。另一独立读数：2 键份额 15%→40%（n2 900→2400）对 T₂ 无可测增益 ⇒ **2 键只需要覆盖下限**。

**C. 错误侧学习曲线**（按行抽样 → 生产脚本；现用户错误率 1.85%）：

| 错误数 | 45 | 100 | 182 | 317 | 548 | 932 |
|---|---|---|---|---|---|---|
| β ± SE | −0.65±0.48 | +0.11±0.33 | +0.33±0.25 | +0.37±0.18 | +0.36±0.14 | +0.32±0.11 |
| δ ± SE | +0.24±0.37 | +0.81±0.22 | +0.86±0.17 | +0.78±0.12 | +0.83±0.09 | +0.82±0.07 |
| 折外 AUC | 0.681 | 0.687 | 0.712 | 0.697 | 0.720 | 0.736 |
| 6 角色 O/E 范围 | [0.00,1.49] | [0.61,1.17] | [0.54,1.05] | [0.79,1.03] | [0.66,1.05] | [0.71,1.05] |

SE ∝ 1/√错误数（如预期）。**δ 只需 ~70 错**（z 已 >3）；**β 要 ~500 错**才到 SE 0.14；**O/E 从 ~180 错起全部落在带内**；AUC 到 932 错仍在缓升。⇒ **错误侧需 ~300–600 错，而非 trial 数**；新用户错误率远高于 1.85%（新手常 3–8%），同样 trial 数攒到的错误多 2–4 倍 ⇒ **错误侧不构成新用户的约束**（换算：5% 错误率下攒 500 错 ≈ 10000 trial）。

**D. 练习期开销**（稳定期边界丢弃 = 新用户同样要付的任务学习成本）：

| 码长 | ok trial | 稳定期 | 保留 |
|---|---|---|---|
| 4 键 | 12872 | 6722 | **52%**（弃 6150） |
| 3 键 | 3331 | 2281 | 68%（弃 1050） |
| 2 键 | 3070 | 3070 | 100%（弃 0） |

4 键弃得最多、2 键不弃——因为 4 键**最先采**（用户当时在建任务熟练度）、2 键 08-29 才加入（此时任务已熟练）⇒ **练习期是一次性任务学习成本，主要由先采的码长承担**。新用户三档同时开采，该成本按 trial 摊到各档。

**结论（新用户）**：

- **比例 = 4键 55% / 3键 25% / 2键 20%**（可行区间 2键 15–25 / 3键 25–30 / 4键 45–60，统计上不可分辨）。4 键给小是因为 T₄ 拐点最高且是主指标；2 键只取覆盖下限（其三项任务 500–1000 trial 即饱和）。
- **总量 ≈ 15700 trial ≈ 纯打字 5–6 小时**：推荐 stable 池 ~9700（4键 5400 / 3键 1800 / 2键 2500，即现用户规模）+ 练习期 ~6000。最低可用 ~6800 stable trial（T₄ 差 0.2ms、T₃/T₂ 差 ~0.5ms）。每试次墙钟 ≈ 固定延迟 550ms + 读码/找键 ~350–500ms + 打字 64/204/385ms（中位）⇒ 加权 ~1.25s/trial。
- **代价-收益提示**：从 4000 涨到 15700 trial（4×）只买到 T₄ <1ms ⇒ 若要「够用就好」，**~7000 trial（含练习期）就能拿到 90% 的精度**；15700 是为「与现用户同级」。
- 局限：曲线取自现用户、且他已是熟练打字者；不同人的练习期长度与错误率水平会移动总样本数（错误率越高越省 trial），**但配比结论对这两者都不敏感**。

## 6. 讨论

### 6.1 局限性

- **串行假设**：段模型假设相邻击键串行。Dhakal et al. (2018) 显示熟练打字员 40-70% 的按键存在 rollover（重叠 30-100ms）——逐段求和可能系统性高估极快打字状态。实测（key-up 字段，释时全>0 无偏口径 11352 行，10-11 晚重算）：重叠比例首段 69.0%、中段 20.2%、尾段 48.5%，幅值中位 28-46ms，与文献区间一致——重叠集中在首段（静止启动加速期）与尾段（提前规划收尾），中段低重叠支持"段模型对中段串行假设最可靠"
- **字母身份残余效应**：刺激以字母呈现，拼音二元组熟悉度对键对耗时存在超出几何/手指特征的小效应（早期全量口径实测）——偏相关 −0.08（控制 φ8 与两键基线后），高熟悉键对比零熟悉约快 7-9ms，与表条目噪声同量级、远小于当量主效应。曾考虑改用键位图显示消除字母层，评估为弊大于利（打字技能按字母组织，位置刺激退化为找键认知任务）——维持字母显示
- **时间漂移（练习效应）**：采集期速度单调提升（早期 session 中段中位 208→157ms，-24.5%），且**按键对类型不均**（同指 -60ms > 同手 -42 ≈ 跨手 -39 > 同键 -13ms）——混期当量表对当前状态的难键对成本系统性高估。处理：**稳定期口径已落地**（§5.1 边界方法自动确定稳定期，训练/测试/部署均只用稳定期数据）
- **误差重尾**：飞行时间近似 log-logistic（重尾），沉思停顿可达数秒；B4b MAD 剔除处理了异常，但纯 MAE 对重尾敏感（可考虑分位数目标）
- **单用户**：模型为个人指法特征（含小指弱势等个体差异），人群外推需 136M Keystrokes 类数据验证

### 6.2 未来工作

（精度类扩容已证无收益，§5.2；下列均为非精度目标或远期条件性条目）

- **外推口径评估**：按三元组留出评估按键时间表外推误差——当前全局 MAE 掩盖了"2/3 条目零样本"的风险分布
- **人群先验**：136M Keystrokes 数据集（168k 人，公开免费）可作稀疏键对的先验/外部验证
- **rollover 显式建模**：key-up 字段已有——串行求和在高重叠段系统性高估，可按重叠类型修正整串口径
- **三元组交互**：Carpalx 的 k1:k2:k3 = 60:30:10 结构提示跨键对涌现惩罚，但三元组覆盖不足下三阶参数只会过拟合——数据量达标后再议
- **错误率数据积累**：~5-10 万 trial 后可升级 26 类指对嵌入/目标指难度特征（当前类别自由参数全部过拟合）

## 7. 结论与应用

本项目将击键时间成本建模从"2 键当量逐对累加"推进为"个人数据驱动的对称条件段模型"：段 S(段角色,p,a,b,n) 统一覆盖 2/3/4 键当量（同源同尺度，含段位/码长角色），错误成本按段角色内含于"当量"定义。**当前（2026-10-11 晚快照，76 session / 20373 行，φ35 三类列序 + 嵌入 12）**：4 键总时间 MAE **35.4ms** / R² +0.668、3 键留出 T₃ **23.5ms**、2 键 T₂ **15.6ms**；绝对标定近完美（×k₄=1.014），三档分别领先群体两键当量表 **35% / 46% / 51%**（§5.3）。**模型已贴实测噪声量级**（§5.2 精度天花板、§5.9 学习曲线 20 倍数据只买 ~6ms），剩余空间属组内生理噪声。

**已关闭的优化方向**（结论与依据见 §4.4 ④–⑳ 一览表与 memory）：模型结构（φ 几何 / 角色特征 / 嵌入维数 / n 通道 / 双线性）、集成（结合器形式 / 成员数 / 分量多样性）、树侧换型与调参、错误率侧特征空间——**全部落在噪声带内**；「冲 36」类测试阈值在旧测试组成下已证不可达，勿再以调模型方式尝试。

**仍开放的项（只有两条，且都不在"调模型"）**：
- **cost 定案（§4.6/§5.7）**——受判据③约束只差 **+278 episode**，前提是坐姿均值走平；`采集-错误修正时间.py` 自 2026-09-13 停更 ⇒ **须重启该采集**。这是唯一真实的采集欠账。
- **可选**：T₃ 偏差 SE 收窄 +546 三键 trial（纯买精度、无行动项，§5.7）。
- 监控项（非欠账）：T₄/T₃/T₂ 的偏差读数（§5.2 表）、L2i1 O/E 是否滑出 [0.55, 1.6]、采集比例与 `MIX` 同步。

**采集现状**：混采比例 = **4键 55% / 3键 25% / 2键 20%**（§5.9 新用户口径；现用户侧欠账已结清），改比例须同步 `采集-按键时间和错误率.py` 的 `P2/P3` 与 `实验-数据充分性估算.py` 的 `MIX`。

应用方式（应用域 = 4 码内词内评估，§4.8）：

- **编码方案评估**：将方案的常用编码代入 总当量-2-4键.txt（错误成本已内含），计算平均击键总时间
- **键位优化**：调整个别键位映射后重新计算总当量，评估优化效果
- **键盘布局设计**：评估新布局的运动学效率（注意模型为 QWERTY 30 键采样训练，非 QWERTY 布局需重新采样）
- **下游直读**：`..\calc-schema\` 与 `D:\chai-windows\` 直接读本机 `产物/段当量表.npz` / `总当量-2-4键.txt`（**改口径或产物结构 = 改下游输入**，见 AGENTS.md 铁律）
